# HOLOS — Episode Configuration v1 Reference

**Project author:** Khaled AL-MAHDY  
**Status:** Documentation of the validator and renderer currently in the repository. This is not a new schema version.

## 1. Purpose and authority

Episode JSON is the declarative input to `tools/holos.py`. It identifies the episode, render profile, audio sources and ordered scene/shot jobs. Frame ranges are half-open: `start_frame` is included and `end_frame` is excluded. Thus a shot with frames 0–240 contains 240 frames.

The current validator is implemented in `holos_engine/config.py`. The renderer also consumes fields that are not all enforced by that validator. Those differences are recorded below rather than hidden.

## 2. Current v1 top-level structure

```json
{
  "schema_version": 1,
  "episode_id": "episode_01",
  "title": "Episode title",
  "description": "Optional description",
  "render": {
    "width": 1280,
    "height": 720,
    "fps": 24,
    "debug_overlay": false
  },
  "audio": {
    "dialogue": null,
    "music": null,
    "music_gain_db": -18,
    "sync_tolerance_ms": 80
  },
  "scenes": [
    {
      "scene_id": "scene_01",
      "title": "Scene title",
      "shots": [
        {
          "shot_id": "S01_B01",
          "start_frame": 0,
          "end_frame": 240,
          "characters": [],
          "scene": "res://scenes/shot_scene.tscn",
          "scene_config": {}
        }
      ]
    }
  ]
}
```

The code currently requires:
- integer `schema_version == 1`;
- non-empty string `episode_id` and `title`;
- positive integer `render.width`, `render.height`;
- positive numeric `render.fps`;
- boolean `render.debug_overlay` when supplied;
- non-empty `scenes` array;
- unique non-empty `scene_id` values;
- non-empty `shots` array for each scene;
- globally unique non-empty `shot_id` values;\n- each shot must define a non-empty Godot `scene` path beginning with `res://`; the Godot runner separately checks that the resource exists and loads as a `PackedScene`;
- integer `start_frame >= 0` and integer `end_frame > start_frame`;
- optional `characters` array of non-empty strings;
- optional `scene_config` object with non-empty string keys;
- optional `audio.dialogue` and `audio.music` as strings or null;
- non-negative numeric `audio.sync_tolerance_ms` (default 80);
- finite `audio.music_gain_db` from -60 to 0 (default -18).

## 3. Additional runtime requirements

The render controller requires each rendered shot to provide a valid Godot scene path under the `scene` property, beginning with `res://`. The generic Godot runner verifies that the resource exists and loads as a PackedScene.

The renderer creates a temporary per-shot config containing:
- `scene`
- `shot_id`
- `start_frame`, `end_frame`
- `fps`, `width`, `height`
- `mode`
- `debug_overlay`
- `scene_config`

The current `examples/episode_01.json` starter contains an explicit replacement `res://` scene path and placeholder timing. It passes structural path validation but is not render-ready: the named scene resource does not exist until replaced with a verified production scene. The validator now catches a missing or malformed scene path before rendering; the Godot runner remains responsible for checking resource existence and loading it as a `PackedScene`.

The example also includes `render.mode`, `video_codec`, `pixel_format`, shot `assets` and shot `notes`. These are not currently enforced by `config.py`; the CLI mode flag controls debug/production mode, and the current assembly implementation explicitly chooses libx264/yuv420p.

## 4. How the relationships work

- Episode → ordered `scenes[]`.
- Scene → ordered `shots[]`.
- Shot → one Godot scene resource, frame interval, optional character identifiers and scene-specific parameters.
- Episode audio → optional dialogue and music file paths.
- Episode render profile → dimensions, frame rate and debug-overlay permission.
- Shot configuration → generated by Python and passed to Godot for the hook contract.

Dialogue text, speaker turns, phoneme timing, voice identity, subtitles and per-line audio segments are **not currently represented** in the validated v1 config contract inspected here. They must not be assumed to be automatically driven by this schema.

## 5. Path and security rules

- IDs used in output directory names must be safe single path components.
- Shot output directories are constrained to the project root.
- The batch and adapter layers reject symlink traversal in protected output paths.
- Dialogue/music paths are resolved beneath the project root by the CLI.
- Godot scenes must use `res://` paths.
- Do not put credentials, API keys, personal tokens or private URLs in episode JSON.
- Do not allow config values to trigger network fetches or arbitrary shell command execution.

## 6. Proposed v2 contract work — not implemented

Before v2, define and test:
1. A checked-in JSON Schema generated from the actual validator contract.
2. Versioned migration policy for the now-required shot `scene` field; safe `res://` path validation is enforced in v1.
3. Explicit `assets[]` declarations with stable asset IDs, hashes and roles.
4. Dialogue segments with stable IDs, speaker IDs, start/end frames, audio asset references and optional alignment references.
5. Character performance blocks with canonical character IDs and adapter-specific state payloads.
6. Audio stems and track policy, including explicit silence and no-audio review mode.
7. Render profile identity/version and codec/pixel-format expectations.
8. Timeline overlap/gap rules and episode-wide frame-rate consistency.
9. Schema migration/version policy and compatibility tests.
10. No implicit defaults for story-critical timing or voice mapping.

Do not silently add these v2 fields to the v1 validator. Keep v1 files readable and create a migration test before changing the contract.

## 7. Example v1 timing calculation

For `fps = 24`:
- `start_frame = 0`
- `end_frame = 240`
- frame count = 240
- duration = 240 / 24 = 10 seconds.

If a shot begins at episode frame 240 and ends at 480, its local PNG sequence still begins at `frame_000000.png`; the manifest retains the episode frame interval.
